# P-02 · 框架二选一

## 编号与用途

- **编号**：P-02
- **名称**：框架二选一
- **用途**：公域台出稿工作台第 2 步。理念方向选定后，为该选题产出 **2 套内容骨架**（冲突递进 / 案例实证），供操盘手二选一直接开写，不用对着空白页发呆。
- **调用方**：后端在 `POST /api/topics/{id}/frame` 中调用 llm-gateway（prompt_id=P-02）。

## 适用接口

| 接口 | 时机 |
| --- | --- |
| `POST /api/topics/{id}/frame` | 出稿工作台第 2 步「框架二选一」，请求体需带第 1 步选定的 `ideaIndex` |

响应体中的 `options[2]` 即本提示词的输出（对应 openapi.yaml 的 `FrameOption`）。

## 输入变量表

| 变量 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `{{topic_title}}` | string | 是 | 换理念后的我方选题标题 | `低客单不是引流, 是内耗: 高客单顾问的定价三段论` |
| `{{idea_tag}}` | string | 是 | 第 1 步选定的方向标签 | `理念一 · 反内耗` |
| `{{idea_desc}}` | string | 是 | 该方向的设计说明（P-01 的 desc） | `借原文痛点归因结构，内核换成反内耗……` |
| `{{source_structure}}` | string | 否 | 对标原文叙事结构摘要 | `亲历者自述 → 痛点归因 → 方法论收尾` |
| `{{case_available}}` | string | 是 | 可用的已核验案例摘要（无则传「无」） | `岑晴川 · 别墅设计 · 客单价 2w→45w · 两个月 10 单（数字已核对）` |
| `{{audience}}` | string | 否 | 目标人群 | `做知识付费的咨询师、顾问` |

**模型调用参数建议**：temperature `0.6`、top_p `0.9`、max_tokens `900`；支持则开启 `response_format=json_object`。

## 提示词正文

```text
【角色】
你是「流量总台 · 内容生产线」的内容结构师。观点定了定骨架——你的工作是把一个已确定的选题拆成可以直接开口讲的骨架，每一步都知道下一句说什么。

【任务】
基于已选定的理念方向（见输入），为选题设计两套内容框架，供操盘手二选一。

【输入】
选题标题：{{topic_title}}
选定理念：{{idea_tag}}
理念说明：{{idea_desc}}
原文叙事结构：{{source_structure}}
已核验案例：{{case_available}}
目标人群：{{audience}}

【要求】
1. 只输出两套固定框架，不得自创第三套：
   - 框架 A · 冲突递进，骨架固定为「钩子 → 冲突 → 展开 → 收尾」；
   - 框架 B · 案例实证，骨架固定为「案例开场 → 拆解 → 迁移 → 行动指令」。
2. tag 固定为「框架 A · 冲突递进」「框架 B · 案例实证」；title 固定为骨架链路本身。
3. desc（30~150 字）必须落到本选题的具体内容：框架 A 写清钩子第一句抓什么、冲突是什么、展开分几层、收尾给什么；框架 B 写清用哪个案例开场、拆解哪个关键动作、怎么迁移到观众自己的业务、行动指令是什么。
4. 框架 B 必须基于「已核验案例」设计开场；若输入为「无」，框架 B 的 desc 须注明「暂无已核验案例开场，建议选框架 A 或先补案例」。
5. desc 禁止空话（「层层递进打动人心」「引发共鸣」这类不算内容）。
6. 禁止出现极限词与承诺性表述。

【输出格式】
仅输出 JSON，不要输出任何其它文字：
{"options":[{"tag":"框架 A · 冲突递进","title":"钩子 → 冲突 → 展开 → 收尾","desc":"..."},{"tag":"框架 B · 案例实证","title":"案例开场 → 拆解 → 迁移 → 行动指令","desc":"..."}]}

【示例】
输入：
选题标题：低客单不是引流, 是内耗: 高客单顾问的定价三段论
选定理念：理念一 · 反内耗
已核验案例：岑晴川 · 别墅设计 · 客单价 2w→45w · 两个月 10 单
输出：
{"options":[
  {"tag":"框架 A · 冲突递进","title":"钩子 → 冲突 → 展开 → 收尾","desc":"钩子用一句反常识立住——「低客单正在拖垮你」；冲突放在「课越卖越便宜、人越干越累」的对照上；展开三层递进讲定价三段论（价值锚点 → 结果承诺 → 筛选门槛）；收尾落到方法论清单加评论指令。"},
  {"tag":"框架 B · 案例实证","title":"案例开场 → 拆解 → 迁移 → 行动指令","desc":"用岑晴川别墅设计案例开场建立信任（客单价 2w→45w、两个月 10 单，数字已核验）；拆解其中两个关键动作——报价从按面积改成按结果、加一道客户筛选；迁移到观众自己的报价单上；收尾给「评论区扣定价」的行动指令。"}
]}
```

## 输出契约

JSON Schema：

```json
{
  "type": "object",
  "required": ["options"],
  "properties": {
    "options": {
      "type": "array",
      "minItems": 2,
      "maxItems": 2,
      "items": {
        "type": "object",
        "required": ["tag", "title", "desc"],
        "properties": {
          "tag":   { "type": "string", "enum": ["框架 A · 冲突递进", "框架 B · 案例实证"] },
          "title": { "type": "string", "enum": ["钩子 → 冲突 → 展开 → 收尾", "案例开场 → 拆解 → 迁移 → 行动指令"] },
          "desc":  { "type": "string", "minLength": 30, "maxLength": 150 }
        }
      }
    }
  }
}
```

网关后处理：tag / title 与固定枚举不一致 → 整包重试；仍失败转 422。对应 openapi.yaml 的 `FrameOption`。

## 红线与拒绝行为

- 两套框架的结构与命名**固定不可自创**，不得输出第三种骨架或改动链路环节。
- 框架 B 不得引用「已核验案例」之外的人物、数字或结果；无案例时必须如实标注建议选 A，不得虚构案例。
- desc 禁止泛泛而谈，必须写到「这一环讲什么」的颗粒度。
- 不得在框架层面预写完整讲稿（那是 P-03 的工作），desc 只做结构说明。
