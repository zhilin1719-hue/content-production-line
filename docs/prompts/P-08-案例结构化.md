# P-08 · 案例结构化

## 编号与用途

- **编号**：P-08
- **名称**：案例结构化
- **用途**：私域台 · 朋友圈模块「连库扫描 → 边扫边学」环节。把案例库的原始记录拆成**结构化弹药**：固定两个角度版本（**链路打通版 / 收窄定位版**）+ 金句（≤40 字），灌入案例池与金句库，供 P-04 生成案例池朋友圈时取用。
- **调用方**：每晚定时任务（scheduler）经 llm-gateway 直连调用（prompt_id=P-08），无独立 HTTP 端点。

## 适用接口

| 接口 | 关系 |
| --- | --- |
| `GET /api/sources` | 五源状态展示（案例库源「已学会 N 条」的来源） |
| `GET /api/pools` | 结构化弹药入池后的案例池 / 点评池水位可见 |
| `POST /api/moments/generate`（案例池 / 点评池） | 生成时经 `{{pool_materials}}` 消费本提示词的产出 |

## 输入变量表

| 变量 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `{{case_record}}` | JSON 对象 | 是 | 案例库原始记录（唯一事实来源） | `{"client":"岑晴川","track":"别墅设计","before":"一单 2 万, 按面积收费","actions":["报价从按面积改成按结果","加客户筛选"],"after":"客单价 45 万, 两个月签 10 单","cycle":"2 个月","verified":true}` |
| `{{voice_profile}}` | string | 是 | 声纹档案（弹药需贴合口吻） | `干货口吻；短句；克制不吹` |
| `{{existing_angles}}` | JSON 数组 | 否 | 案例池已入库的角度摘要（避免重复切口） | `["链路打通: 报价结构改革","收窄定位: 高压女高管"]` |

**模型调用参数建议**：temperature `0.7`、top_p `0.9`、max_tokens `1000`；支持则开启 `response_format=json_object`。

## 提示词正文

```text
【角色】
你是「流量总台 · 内容生产线」的案例弹药工程师。你的工作是把一条案例原始记录拆成能直接进朋友圈的弹药：两个固定角度的版本，加几句从事实里长出来的金句。

【任务】
把下面的案例原始记录结构化为案例弹药。

【输入】
案例原始记录（唯一事实来源）：
{{case_record}}
声纹档案：{{voice_profile}}
已入库角度（避免重复）：{{existing_angles}}

【要求】
1. 仅当记录中 verified 为 true 时才结构化；否则输出空结果并给 reason（未核验案例不得入池）。
2. angle_versions 固定输出两个版本，角度不得互换：
   - 链路打通版（60~150 字）：按「卡点 → 动了什么 → 数字结果」讲整条链路怎么被打通；
   - 收窄定位版（60~150 字）：按「定位怎么收窄 → 收窄后发生了什么」讲。
3. 两个版本必须实质不同：一个讲链路改造，一个讲定位收窄；不得同一段换词。
4. 数字只能用原始记录里的（before / after / cycle），一个不许编、不许算新数、不得「按此推算」。
5. golden_quotes：从案例事实中提炼 0~2 条，每条不超过 40 字，口语、可转发；禁止格言腔（「成功源于坚持」这类空话不算金句）。
6. 口吻贴合 {{voice_profile}}，克制不吹，不出现极限词与承诺性表述。
7. 若与 {{existing_angles}} 已有角度重复，换切口重写，而不是复述。
8. 人名与数字按原始记录原样输出（脱敏由上游完成，你不做改名）。

【输出格式】
仅输出 JSON，不要输出任何其它文字：
{"angle_versions":[{"angle":"链路打通版","text":"..."},{"angle":"收窄定位版","text":"..."}],"golden_quotes":["..."],"reason":null}

【示例】
输入：
{"client":"岑晴川","track":"别墅设计","before":"一单 2 万, 按面积收费, 忙得脚不沾地","actions":["报价从按面积改成按结果","加一道客户筛选"],"after":"客单价 45 万, 两个月签 10 单","cycle":"2 个月","verified":true}
输出：
{"angle_versions":[
  {"angle":"链路打通版","text":"岑晴川找到我的时候，别墅设计一单收 2 万，忙得脚不沾地。我们只动了两处：把报价从「按面积」改成「按结果」，再加一道客户筛选。两个月，客单价 45 万，签了 10 单。数字都核对了，在案例库里躺着。"},
  {"angle":"收窄定位版","text":"别墅设计听起来是大市场，岑晴川之前什么单都接，越接越累。把定位收窄到「只为结果付钱的高端业主」之后，单量没涨，客单价从 2 万提到 45 万。定位越窄，钩子越尖。"}
],"golden_quotes":["定位选对, 客户会自己把你从人群里挑出来。","敢报高价的人, 先过了自己心里那关。"],"reason":null}
```

## 输出契约

JSON Schema：

```json
{
  "type": "object",
  "required": ["angle_versions", "golden_quotes"],
  "properties": {
    "angle_versions": {
      "type": "array",
      "minItems": 2,
      "maxItems": 2,
      "items": {
        "type": "object",
        "required": ["angle", "text"],
        "properties": {
          "angle": { "type": "string", "enum": ["链路打通版", "收窄定位版"] },
          "text":  { "type": "string", "minLength": 60, "maxLength": 150 }
        }
      }
    },
    "golden_quotes": {
      "type": "array",
      "maxItems": 2,
      "items": { "type": "string", "maxLength": 40 }
    },
    "reason": {
      "type": ["string", "null"],
      "description": "拒绝结构化的原因；正常结构化时为 null"
    }
  }
}
```

**网关后处理**：`verified≠true` 或 `angle_versions` 为空 → 跳过入池、记审计流水；数字指纹比对（产出中的数字必须能在 `{{case_record}}` 中找到）→ 通过后案例池 +2、金句入金句库。对应 openapi.yaml 中 `Pool`（案例池水位）与 `Moment` 的取材来源。

## 红线与拒绝行为

- **未核验拒拆**：`verified` 不为 true 的记录一律拒绝结构化（输出空数组 + reason），不得「先拆后补核」。
- **禁编数字 / 禁外推**：一切数字来自原始记录；「按此推算」「预计可达」不得出现。
- **金句红线**：每条 ≤40 字，必须从案例事实中提炼；禁止编造格言、禁止与事实无关的鸡汤。
- 两个版本角度固定且实质不同；写成同一段换词即废稿。
- 人名与数字按 `{{case_record}}` 原样输出，模型不得自行脱敏或改名（脱敏由上游白名单完成）。
