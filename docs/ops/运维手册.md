| 项 | 内容 |
|---|---|
| 适用版本 | v1.0（health 返回 version 1.0.0-d2 系列） |

## 1. 架构说明

一句话：零依赖 Node 单机服务 + JSON 文件存储 + 原型静态托管，单进程跑完所有事。

| 组件 | 说明 |
|---|---|
| HTTP 服务 | server/server.js，仅用 Node 内置 http 模块，单进程；API 与静态托管同端口 8399 |
| 业务引擎 | server/engines.js：选题生成、初稿、合规扫描（规则库 + 语义词表）、原创度（连续 8 字重合 ≤15%）、像你度（≥90 出稿，<90 自动重写一次） |
| LLM 网关 | server/llm-gateway.js：主备双供应商，主故障自动切备；prompt 从 server/prompts/ 加载（P-01 ~ P-08） |
| 持久化 | server/store.js → server/data/*.json；写盘防抖 50ms，原子写（先写 .tmp 再 rename），进程退出前 flush |
| 种子数据 | server/seed.js：首次启动自动播种两个演示项目与五个演示账号；`node seed.js --reset` 可强制重置 |
| 静态托管 | ../app 目录：index.html（总台看板）、gongyu.html（公域台）、quan.html（朋友圈台）、kaike.html（公开课台）+ assets |
| 鉴权 | HMAC 签名 Bearer token，有效期 7 天；角色四类（admin / operator / reviewer / viewer），跨项目访问统一 404 |

启动与停止：

```bash
cd server
node server.js          # 启动，控制台输出 API 地址 / 门户地址 / 数据目录
# 停止：Ctrl+C（SIGINT/SIGTERM 均会先 flushAll 再退出，数据不丢）
```

## 3. 日常巡检清单（每日一次，建议 09:30）

| # | 项目 | 操作 / 命令 | 通过标准 | 不通过怎么办 |
|---|---|---|---|---|
| 1 | 健康检查 | `curl http://127.0.0.1:8399/api/health` | HTTP 200，`ok: true`，version 与部署版本一致 | 见《告警处置单》卡片 2 |
| 2 | 进程存活 | 任务管理器查 node 进程（或 `tasklist /fi "imagename eq node.exe"`） | 存在且 CPU 无持续占满 | 进程不在 → 重启并按卡片 1 处置 |
| 3 | 磁盘占用 | 查数据盘剩余空间 | 使用率 < 80% | ≥80% 按卡片 4 处置 |
| 4 | 备份产物核验 | 检查昨日 tar 文件存在、大小 > 0，抽查一个 json 可解析 | 三项全过 | 按卡片 5 处置，当日补做全量备份 |
| 5 | 错误日志扫描 | 查看控制台/日志中 `[cpl-server] error:` 计数 | 当日 0 条 | 有则记录错误码，对应告警卡片处置 |
| 6 | 关键接口冒烟 | 登录 → GET /api/topics?projectId=p-zeyu → GET /api/pools | 全部 200，数据非空 | 任一失败按卡片 1/3 排查 |

## 4. 日志与审计查看

| 内容 | 位置 / 接口 | 说明 |
|---|---|---|
| 服务日志 | 进程控制台（前缀 `[cpl-server]`） | 启动信息、错误堆栈；建议以 PM2/nssm 或重定向方式常驻并留存 |
| 业务审计 | `GET /api/audit`（管理员） | 谁在何时对哪个对象做了什么写操作；支持 actor、action 过滤，limit 默认 100、上限 500 |
| 费用与调用 | `GET /api/cost-report`（管理员） | LLM 调用次数、token 估算（字符数/4）、按项目与按 prompt 维度、主备切换次数 |
| 数据落盘 | server/data/*.json | 按集合分文件：projects / users / accounts / topics / drafts / moments / sessions / materials / course / pools / audit / ledger / scan_log / signals / costs |

## 5. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| PORT | 8399 | 服务端口 |
| DATA_DIR | server/data | 数据目录（可指向备份恢复用临时目录，测试已用此变量隔离） |
| HOST | 127.0.0.1 | 监听地址；需局域网访问时改为 0.0.0.0 并自行保证网络边界 |
| AUTH_SECRET | 内置演示值 | token 签名密钥；正式启用必须改为自定义强随机值（改动后所有已发 token 失效，需重新登录） |
| LLM_PROVIDER | 空（正常） | `fail` 注入主供应商故障验证自动切备；`fail-all` 主备全挂（接口返回 503，用于演练） |
| LLM_DELAY_MS | 200–600 随机 | 生成类接口模拟延迟；测试时可设 1 加速 |

## 6. 性能与容量注意

- 单机单进程，无外部数据库。读写均在内存缓存 + 防抖落盘，列表接口分页 20 条/页，请求体上限 1MB。
- 当前规模（2 个演示项目、单项目数据文件 < 1MB）：日常数十并发访问无压力；`node test/_load.js` 可做压测验证。
- 容量预估：以每项目每天 50 条写操作计，单项目数据年增长在几十 MB 量级。数据文件到几十 MB 级时列表加载会开始变慢，届时应评估迁移到正式数据库（属于二期范围，不在本期服务边界内）。
- 生成类接口延迟 200–600ms（模拟 LLM）；若主供应商故障自动切备，单次请求会多一次重试延迟，前端表现为偶发慢 1 秒，属正常降级。
- 磁盘水位 80% 是处置线：JSON 原子写需要临时文件空间，磁盘满会直接导致写失败。

## 7. 常用操作速查

| 场景 | 操作 |
|---|---|
| 首次部署 | `cd server && node server.js`（首启自动播种演示数据） |
| 重置为演示初始态 | `node seed.js --reset`（清空 DATA_DIR 后重新播种，慎用） |
| 验证主备切换 | 设 `LLM_PROVIDER=fail` 启动，生成类接口仍可用，/api/cost-report 的 failovers +1 |
| 演练全挂返回 | 设 `LLM_PROVIDER=fail-all` 启动，生成类接口返回 503 |
| 查看数据快照 | 直接读取 server/data/*.json（建议先停服或复制后读，避免读到写一半的临时文件） |
